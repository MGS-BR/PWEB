1. Introdução

Contexto e Governança

A engenharia de software contemporânea fundamenta-se no princípio do reuso para elevar a qualidade e reduzir o esforço de desenvolvimento. Nesse contexto, os frameworks representam uma das abordagens mais eficazes, permitindo que uma família de produtos seja gerada a partir de uma estrutura única que captura conceitos gerais de um domínio.

A adoção de frameworks não é apenas uma escolha técnica, mas uma decisão estratégica de Governança de TI, que deve alinhar a metodologia escolhida aos objetivos e estratégias organizacionais para garantir resultados eficientes e menor tempo de projeto.


Princípio de Design

"Don't call us, we will call you" (Princípio de Hollywood - Inversão de Controle).

2. Fundamentação Teórica e Definições

Definição Acadêmica

A âncora principal da teoria sobre frameworks na literatura acadêmica é o trabalho de Fayad & Schmidt (1997), que define um framework como um conjunto integrado de artefatos de software (como classes, objetos e componentes) que colaboram para fornecer uma arquitetura reusável para uma família de aplicações relacionadas.


Características Distintivas

  1. Inversão de Controle (IoC): Também conhecida como o "Princípio de Hollywood" (Don't call us, we will call you), onde o framework assume o controle da execução e invoca métodos da aplicação em resposta a eventos específicos.
  2. Software Parcialmente Completo: É uma estrutura inacabada projetada para ser instanciada, oferecendo construtores básicos e definindo uma arquitetura comum.
  3. Hot-spots (Pontos de Extensão): São locais explicitamente definidos onde o desenvolvedor deve adaptar o código para funcionalidades específicas de certos módulos.

3. Classificação dos Frameworks

Técnicas de Extensão e Escopo

Os frameworks podem ser classificados segundo sua técnica de extensão ou escopo de aplicação no ecossistema HTML, CSS e JavaScript:

3.1. Quanto à Técnica de Extensão
Caixa Branca (White-box): A extensão ocorre principalmente via herança, exigindo que o desenvolvedor conheça a estrutura interna para implementar métodos abstratos ou redefinir métodos ganchos (hook methods).
Caixa Preta (Black-box): A extensão é feita via composição e configuração, seguindo interfaces ou contratos definidos, sendo geralmente mais fáceis de usar por não exigirem conhecimento profundo do código interno.
Caixa Cinza (Gray-box): Combina características de ambos os modelos para mitigar suas desvantagens individuais.
3.2. Quanto ao Escopo de Aplicação
Infraestrutura de Sistemas: Simplificam o desenvolvimento de sistemas operacionais, frameworks de comunicação e interfaces gráficas.
Integração de Middleware: Utilizados para integrar aplicações distribuídas, ocultando detalhes de baixo nível da comunicação entre componentes.
Aplicações Corporativas: Voltados para domínios específicos (ex: financeiro, aviação ou telecomunicações), encapsulando conhecimento especializado do setor.

5. Critérios de Escolha e Seleção

A escolha de um framework deve considerar: Comunidade e Suporte, Curva de Aprendizado, Escalabilidade e Manutenibilidade, Segurança (com proteções nativas contra SQL Injection, XSS e CSRF), Mercado/Ecossistema e Desempenho.


6. Conclusão

Os frameworks são ativos estratégicos indispensáveis para a produtividade no desenvolvimento de software moderno. Não existe um framework universalmente superior; a decisão correta depende da análise criteriosa do domínio, da experiência da equipe e da sustentabilidade a longo prazo do projeto.
